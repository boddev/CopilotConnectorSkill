# Building Copilot Connectors with the Microsoft 365 Agents Toolkit

Build and deploy Copilot Connectors using the Microsoft 365 Agents Toolkit — a template-based approach with integrated scaffolding, app registration, and F5 (press-to-run) local development.

## Overview

The **Microsoft 365 Agents Toolkit** (formerly Teams Toolkit) is a VS Code extension that provides a streamlined developer experience for building Copilot Connectors. Instead of manually creating Entra ID app registrations, writing boilerplate Graph API code, and configuring schema registration, the toolkit scaffolds a complete project with:

- **TypeScript + Azure Functions** project structure for local development and cloud deployment
- **F5 experience** — press F5 to provision, register the schema, and start ingesting items locally
- **Automatic Entra ID app registration** — the toolkit creates and configures the app for you
- **Admin consent flow** — guided link in the terminal output
- **Schema registration** — template-driven, with polling built in
- **Full crawl lifecycle** — built-in connection management, schema provisioning, and item ingestion

> **Official docs:** [Build your first connector with Agents Toolkit](https://learn.microsoft.com/microsoft-365/copilot/extensibility/build-your-first-connector)

## Prerequisites

| Requirement | Details |
|-------------|---------|
| **Visual Studio Code** | Latest version |
| **Microsoft 365 Agents Toolkit** | VS Code extension (search "Microsoft 365 Agents Toolkit" in the Extensions marketplace) |
| **Azure Functions extension** | VS Code extension for Azure Functions |
| **Node.js** | Version 18, 20, or 22 |
| **Microsoft 365 Copilot license** | Or a [Microsoft 365 Developer Program](https://developer.microsoft.com/microsoft-365/dev-program) tenant |
| **Global Administrator access** | Required to grant admin consent for the connector's app registration |
| **Search Administrator role** | Required to enable inline results in M365 Admin Center |

## Quick Start

### Step 1: Create the Project

1. Open **VS Code**
2. Open the **Agents Toolkit** sidebar (shield icon)
3. Click **Create New Agent/App**
4. Select **Copilot connector**
5. Enter a **connector name** (display name shown in M365 Admin Center)
6. Enter a **unique connection ID** (3–128 alphanumeric characters, unique per tenant)
7. The toolkit scaffolds the project and installs dependencies

### Step 2: Configure Your Data Source

Open `.env.local` and configure your external data source connection details:

```env
# .env.local — generated by the toolkit
# [Customization point] Replace these with your data source credentials
CONNECTOR_ID=contosohelpdesk
CONNECTOR_DISPLAY_NAME=Contoso Helpdesk
DATA_SOURCE_URL=https://api.contoso.com
DATA_SOURCE_API_KEY=your-api-key-here
```

### Step 3: Run Locally (F5)

1. Press **F5** (or Run → Start Debugging)
2. The toolkit will:
   - Create the Entra ID app registration (first run only)
   - Provision the connection in Microsoft Graph
   - Register the schema
   - Start the Azure Functions host locally
3. Watch the terminal — it will show a link to **grant admin consent** in the Entra admin center

### Step 4: Grant Admin Consent

1. Click the **Entra admin center link** shown in the terminal output
2. Sign in as a **Global Administrator**
3. Review and grant the requested permissions:
   - `ExternalConnection.ReadWrite.OwnedBy`
   - `ExternalItem.ReadWrite.OwnedBy`

### Step 5: Wait for Schema Registration

Schema registration is asynchronous and can take **up to 10 minutes**. The toolkit polls automatically — watch the terminal for status updates.

### Step 6: Enable Inline Results

1. Go to **[M365 Admin Center](https://admin.microsoft.com)** → **Search & intelligence** → **Data sources**
2. Find your connector in the list
3. Toggle **Include connector results for inline results** to **On**
4. Optionally configure a custom search vertical under **Customizations** → **Verticals**

### Step 7: Assign Search Administrator Role

If you haven't already, assign the **Search Administrator** role to the user who will manage the connector visibility:

1. Go to **[M365 Admin Center](https://admin.microsoft.com)** → **Roles** → **Role assignments**
2. Search for **Search Administrator** and assign to the appropriate user

### Step 8: Test in M365 Copilot

1. Open **[M365 Copilot Chat](https://m365.cloud.microsoft/chat)**
2. Ask a question that relates to your connector's data, e.g.:
   - *"Find open helpdesk tickets about VPN issues"*
   - *"What helpdesk tickets are assigned to Jane Smith?"*
3. Copilot should return results from your connector, with citations linking to the source items

## Project Structure

The Agents Toolkit scaffolds the following project structure:

```
├── src/
│   ├── custom/              # [Customization point] Your data source integration
│   │   ├── dataSource.ts    # Fetch and transform data from your external source
│   │   └── ...
│   ├── references/          # [Customization point] Schema definition
│   │   ├── schema.ts        # Property definitions, types, labels, and aliases
│   │   └── ...
│   ├── models/              # Data models and configuration
│   │   ├── connection.ts    # Connection ID, name, description
│   │   └── ...
│   ├── functions/           # Azure Functions entry points
│   │   ├── crawl.ts         # Full crawl trigger (timer or HTTP)
│   │   ├── provision.ts     # Connection + schema provisioning
│   │   └── ...
│   └── services/            # Microsoft Graph API interaction layer
│       ├── graphService.ts  # Graph client for connection/schema/item operations
│       └── ...
├── .env.local               # Local environment configuration
├── .env.local.user          # Local secrets (not committed to source control)
├── teamsapp.yml             # Agents Toolkit lifecycle configuration
├── teamsapp.local.yml       # Local debug configuration
├── host.json                # Azure Functions host configuration
├── local.settings.json      # Azure Functions local settings
└── package.json             # Node.js dependencies
```

### Key Files to Customize

| File | What to Change | Why |
|------|---------------|-----|
| `src/custom/dataSource.ts` | Replace GitHub API calls with your data source | The template uses GitHub Issues as a sample; swap in your API/database |
| `src/references/schema.ts` | Adjust properties, types, labels, and aliases | Match the schema to your data's structure |
| `src/models/connection.ts` | Update connection ID, name, and description | The description tells Copilot when to use your data |
| `.env.local` | Set data source credentials and URLs | Connect to your actual data source |

> **Tip:** Search for `[Customization point]` comments in the scaffolded code to find all the places that need your input.

## Customization Guide

### Replacing the Data Source

The scaffolded project uses a sample data source (typically GitHub Issues). To connect your own data:

1. **Update `src/custom/dataSource.ts`** — Replace the `fetchItems()` function with calls to your API or database. See [data-source.ts](data-source.ts) for a complete example.

2. **Update `src/references/schema.ts`** — Define properties that match your data's fields. See [connector-config.ts](connector-config.ts) for a complete schema example.

3. **Update `src/models/connection.ts`** — Write a rich, descriptive connection description that tells Copilot what your data contains and when to surface it.

4. **Map properties** — In your `transformToExternalItem()` function, map each source field to the corresponding schema property.

### Schema Considerations

The same schema design rules apply whether you use the Agents Toolkit or the direct SDK:

- **`searchable` and `refinable` are mutually exclusive** — decide at design time
- **Cannot add `refinable` via schema update** — must be set in the initial schema
- **Always assign semantic labels:** `title`, `url`, `iconUrl` at minimum
- **Properties with labels must be `retrievable`**

See the [schema design reference](../../references/schema-design.md) for complete guidance.

## Deployment

### Local Development (F5)

The F5 experience uses **Azure Functions Core Tools** to run the connector locally. The toolkit handles:

- Entra ID app provisioning (via `teamsapp.local.yml`)
- Connection creation and schema registration
- Local function host startup
- Admin consent guidance

### Deploy to Azure

1. Open the **Agents Toolkit** sidebar
2. Click **Deploy** (under "Lifecycle")
3. Select your Azure subscription and resource group
4. The toolkit deploys to **Azure Functions** and configures the production environment

The deployment process:
- Creates Azure Functions resources (if not already provisioned)
- Deploys the compiled TypeScript code
- Configures environment variables from `.env` files
- Sets up the production Entra ID app registration

### Manual Deployment

If you prefer to deploy manually:

```bash
# Build the project
npm run build

# Deploy to Azure Functions (requires Azure Functions Core Tools)
func azure functionapp publish <your-function-app-name>
```

## Agents Toolkit vs Direct SDK

| Factor | Agents Toolkit | Direct SDK (C#/Python/Java/TS) |
|--------|---------------|-------------------------------|
| **Setup speed** | Fast — scaffolded project with F5 | Manual project setup and configuration |
| **App registration** | Automatic via toolkit | Manual Entra ID registration |
| **Schema registration** | Template-driven with polling | Code-driven, implement polling yourself |
| **Deployment target** | Azure Functions | Any hosting (Azure, AWS, on-premises) |
| **Full crawl management** | Built-in lifecycle functions | Custom implementation required |
| **Admin consent** | Guided link in terminal | Manual consent flow |
| **Learning curve** | Lower for new projects | Lower for experienced Graph API developers |
| **Flexibility** | Template-constrained | Full control over architecture |
| **Language** | TypeScript | C#, Python, Java, TypeScript, any (REST) |
| **Best for** | New connectors, prototyping, agent + connector combos | Production systems needing full architectural control |

**Choose the Agents Toolkit when:**
- You're building a new connector from scratch
- You want the fastest path to a working connector
- You're also building a Declarative Agent that uses the connector
- Your team is comfortable with TypeScript and Azure Functions

**Choose the direct SDK when:**
- You need full control over hosting, lifecycle, and error handling
- Your connector is part of a larger application with existing infrastructure
- You're working in C#, Python, or Java
- You need on-premises deployment or custom crawl scheduling

## Using Connectors with Declarative Agents

Copilot Connectors can serve as **knowledge sources** for Declarative Agents. This means you can build an AI agent that is specialized to answer questions using your connector's data.

### How It Works

1. **Build the connector** — Create and deploy your Copilot Connector (using either the Agents Toolkit or direct SDK)
2. **Create a Declarative Agent** — Define an agent with instructions, conversation starters, and capabilities
3. **Reference the connector** — In the agent definition, add the connector as a `GraphConnectors` capability using the connection ID

### TypeSpec Example

See [declarative-agent-connector.tsp](declarative-agent-connector.tsp) for a complete example of a Declarative Agent that references a Copilot Connector.

### Agents Toolkit Integration

The Agents Toolkit can scaffold both a connector and a Declarative Agent together:

1. Create the connector project as described above
2. Add a Declarative Agent to the same project via the Agents Toolkit
3. In the agent's definition, reference the connector's connection ID
4. Both are deployed and managed together

### Best Practices for Agents with Connectors

- **Write clear agent instructions** — Tell the agent what the connector data contains and how to interpret it
- **Add conversation starters** — Provide example queries so users know what to ask
- **Handle aggregation limitations** — Instruct the agent to look for pre-computed summary items rather than counting individual results
- **Use multiple connectors** — A single agent can reference multiple connectors as knowledge sources

## Troubleshooting

| Issue | Solution |
|-------|----------|
| F5 fails with auth error | Ensure you're signed into the Agents Toolkit with a Global Admin account |
| Schema registration times out | Check the terminal for error details; verify the schema is valid (no conflicting attributes) |
| Items don't appear in Copilot | Enable inline results in M365 Admin Center → Search & intelligence → Data sources |
| Admin consent link not shown | Re-run F5; the link appears on first provisioning or when consent hasn't been granted |
| Connection already exists | Use a different connection ID, or delete the existing connection via Graph Explorer |
| Schema has `searchable + refinable` | These are mutually exclusive — choose one per property |
